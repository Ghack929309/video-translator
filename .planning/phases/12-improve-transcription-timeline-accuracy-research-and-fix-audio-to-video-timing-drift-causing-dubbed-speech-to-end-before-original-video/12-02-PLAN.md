```typescript
// Phase 12: Revised gap-aware pacing — always enforce segment duration
const targetDurationSec = segDurationSec; // Always target the segment duration
const tolerance = 0.10; // 10% tolerance
const relativeDiff = Math.abs(actualGeneratedSec - targetDurationSec) / targetDurationSec;

if (relativeDiff < tolerance) {
  // Within 10% of target — use as-is (no stretching needed)
  audioParts.push({ path: rawPath, startMs: seg.start });
  console.log(
    `[pipeline] Seg ${i}: target=${targetDurationSec.toFixed(2)}s ` +
    `actual=${actualGeneratedSec.toFixed(2)}s — within ${(tolerance * 100).toFixed(0)}% tolerance, using as-is`
  );
} else if (actualGeneratedSec > targetDurationSec) {
  // TTS is LONGER than segment
  const gapSec = (nextSegStart - seg.end) / 1000;
  if (gapSec > 0 && actualGeneratedSec <= targetDurationSec + gapSec * 0.8) {
    // Fits within segment + 80% of gap — allow natural overflow
    audioParts.push({ path: rawPath, startMs: seg.start });
    console.log(
      `[pipeline] Seg ${i}: overflow into gap ` +
      `(${actualGeneratedSec.toFixed(2)}s into ${targetDurationSec.toFixed(2)}s + ${gapSec.toFixed(2)}s gap)`
    );
  } else {
    // Too long even with gap — speed up to fit in segment
    const { outputPath: finalPath } = await ffmpeg.timeStretchExact(
      rawPath, targetDurationSec, stretchedPath
    );
    audioParts.push({ path: finalPath, startMs: seg.start });
    console.log(
      `[pipeline] Seg ${i}: sped up ${actualGeneratedSec.toFixed(2)}s -> ${targetDurationSec.toFixed(2)}s`
    );
  }
} else {
  // TTS is SHORTER than segment — stretch to fill the slot
  const { outputPath: finalPath } = await ffmpeg.timeStretchExact(
    rawPath, targetDurationSec, stretchedPath
  );
  audioParts.push({ path: finalPath, startMs: seg.start });
  console.log(
    `[pipeline] Seg ${i}: stretched ${actualGeneratedSec.toFixed(2)}s -> ${targetDurationSec.toFixed(2)}s`
  );
}
```

Key differences from the old logic:
1. The OLD code checked `actualGeneratedSec <= segDurationSec + gapSec` which allowed SHORT TTS to pass through. The NEW code only allows gap overflow when TTS is LONGER than the segment.
2. The OLD code had a flat `< 0.1` absolute tolerance. The NEW code uses 10% relative tolerance.
3. The NEW code always stretches SHORT TTS to fill the segment slot. This is the primary fix for the timing drift.
4. The gap overflow check uses `gapSec * 0.8` (80% of gap) instead of the full gap, to leave some breathing room.
5. Every branch logs segment-level diagnostics for production debugging.

Make sure to preserve the try/catch around this block (the TTS failure handling with failedSegments is around this code and must remain intact).
