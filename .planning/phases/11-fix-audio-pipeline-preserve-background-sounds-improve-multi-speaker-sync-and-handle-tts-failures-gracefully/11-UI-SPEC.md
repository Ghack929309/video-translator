## UI Addition 1: Background Audio Ducking Toggle

**Location:** `app/routes/platform/new-translation.tsx`, below the Target Language field, above the Video Title field.

**Decision source:** D-06 -- "Background audio ducking is a simple on/off toggle in the UI (default: on, -8dB during speech). Not a slider or multi-level control."

### Layout

```
Target Language
[ Search languages...                          v ]

Preserve Background Audio                    [====]
Keep music, ambient sounds, and other         ^
background audio in the translated video.     Switch (default: on)
When enabled, background audio is ducked
(-8dB) during speech.
```

### Specifications

| Property | Value |
|----------|-------|
| Container | `flex items-center justify-between gap-4` inside a `div.space-y-2` |
| Label text | "Preserve Background Audio" |
| Label element | `<Label htmlFor="enableBackgroundMix">` at 14px, weight 500 |
| Help text | "Keep music, ambient sounds, and other background audio in the translated video. When enabled, background audio is ducked during speech." |
| Help text style | `text-xs text-muted-foreground` (12px, muted) |
| Switch component | shadcn `Switch`, size `default` (18.4px height, 32px width) |
| Switch default state | `checked` (on) -- matches D-06 default |
| Hidden input name | `enableBackgroundMix` |
| Hidden input value | `"true"` when checked, `"false"` when unchecked |
| Spacing from previous field | `gap-4` (16px) via parent `space-y-4` |

### Interaction States

| State | Visual |
|-------|--------|
| Default (checked) | Switch shows `bg-primary` (purple), thumb at right |
| Unchecked | Switch shows `bg-input` (muted gray), thumb at left |
| Disabled (during submission) | `opacity-50 cursor-not-allowed` (Switch built-in) |
| Focus | `border-ring ring-3 ring-ring/50` (Switch built-in) |

### Code Pattern

```tsx
{/* Between Language Selector and Video Title */}
<div className="flex items-center justify-between gap-4">
  <div className="space-y-0.5">
    <Label htmlFor="enableBackgroundMix">Preserve Background Audio</Label>
    <p className="text-xs text-muted-foreground">
      Keep music, ambient sounds, and other background audio in the translated video.
    </p>
  </div>
  <Switch
    id="enableBackgroundMix"
    defaultChecked
    onCheckedChange={(checked) => setEnableBackgroundMix(checked)}
  />
</div>
```

Hidden form field pattern (matches existing engine/language hidden fields):

```tsx
<input type="hidden" name="enableBackgroundMix" value={enableBackgroundMix ? "true" : "false"} />
```

## UI Addition 2: Failed Segment Warning

**Location:** `app/routes/platform/translation.tsx`, between the Pipeline Progress card and the Translation Details card. Only visible when `failedSegmentCount > 0` AND status is `COMPLETED` or `PROCESSING`.

**Decision source:** D-13 -- "Surface in the UI: 'Warning: X of Y segments could not be synthesized.'"

### Layout

```
+---------------------------------------------------------+
|  /!\  Some segments could not be synthesized             |
|                                                          |
|  3 of 24 segments failed during voice synthesis and      |
|  were replaced with silence. The translation is          |
|  otherwise complete.                                     |
+---------------------------------------------------------+
```

### Specifications

| Property | Value |
|----------|-------|
| Container | `div` with `rounded-md border border-amber-500/30 bg-amber-500/10 px-4 py-3` |
| Icon | `AlertTriangle` from lucide-react, `h-4 w-4 text-amber-500`, inline with heading |
| Heading | "Some segments could not be synthesized" at 14px, weight 500 |
| Heading layout | `flex items-center gap-2` with icon |
| Body text | "{failedSegmentCount} of {totalSegmentCount} segments failed during voice synthesis and were replaced with silence." |
| Body text style | `text-sm text-amber-500/90 mt-1` |
| Conditional suffix | If status is `COMPLETED`: append "The translation is otherwise complete." |
| Visibility condition | `failedSegmentCount > 0` |
| Placement | After the Pipeline Progress `Card`, before the Translation Details `Card` |

### Color Rationale

The warning uses `amber-500` (not `destructive` red) because the translation succeeded with partial degradation. Red is reserved for full failures per the established `StatusBadge` convention. Amber communicates "completed with caveats" -- the user got a result, but it has known gaps.

### Data Requirements

The loader must include two new fields from the Translation record:

| Field | Type | Source |
|-------|------|--------|
| `failedSegmentCount` | `number` | `translation.failedSegmentCount` (new Prisma field, default 0) |
| `totalSegmentCount` | `number` | Derived from `translation.translatedJson` array length, or 0 |

### Interaction States

| State | Behavior |
|-------|----------|
| `failedSegmentCount === 0` | Component not rendered |
| `failedSegmentCount > 0, status COMPLETED` | Show warning with "otherwise complete" suffix |
| `failedSegmentCount > 0, status PROCESSING` | Show warning without suffix (still processing) |
| `failedSegmentCount > 0, status FAILED` | Not shown -- the existing FAILED error card already covers this case |

## UI Addition 3: Updated Pipeline Steps

**Location:** `app/components/translation-progress.tsx`, STEPS array constant.

**Decision source:** D-04 -- "Add a new pipeline step `SEPARATE_AUDIO` between EXTRACT_AUDIO and TRANSCRIBE."

### Updated STEPS Array

```typescript
const STEPS = [
  { key: "DOWNLOAD", label: "Download Video" },
  { key: "EXTRACT_AUDIO", label: "Extract Audio" },
  { key: "SEPARATE_AUDIO", label: "Separate Background" },  // NEW
  { key: "TRANSCRIBE", label: "Transcribe Speech" },
  { key: "TRANSLATE", label: "Translate Text" },
  { key: "CLONE_VOICE", label: "Clone Voice" },
  { key: "SYNTHESIZE", label: "Synthesize Speech" },
  { key: "MERGE", label: "Merge Video" },
];
```

### Label Choice

"Separate Background" (not "Separate Audio" or "Source Separation") because:
- It describes the user-facing outcome, not the technical process
- It is concise (fits the same visual width as other labels)
- It pairs naturally with the "Preserve Background Audio" toggle

### Visual Impact

The progress grid now shows 8 steps instead of 7. No layout changes required -- the existing vertical list with `space-y-1` and the step icon + label pattern scales to any number of steps. The `getStepStatus` function works index-based against the STEPS array and requires no logic changes.

### Progress Percentages (Backend)

These are set in `pipeline.server.ts`, not in the UI, but documented here for UI-backend alignment:

| Step | Progress Value |
|------|---------------|
| DOWNLOAD | 8% |
| EXTRACT_AUDIO | 15% |
| SEPARATE_AUDIO | 25% |
| TRANSCRIBE | 38% |
| TRANSLATE | 50% |
| CLONE_VOICE | 60% |
| SYNTHESIZE | 80% |
| MERGE | 95% |

Source: RESEARCH.md recommended values.
